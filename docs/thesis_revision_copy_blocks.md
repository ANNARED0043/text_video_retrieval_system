### 1.1.3 当前视频检索面临的主要问题

**建议替换/增补文本**

```text
当前自然语言视频检索仍面临三类主要问题。第一，文本与视频之间存在明显模态差异，文本通常是离散、抽象且压缩的语义表达，而视频则包含连续帧、运动模式和复杂背景信息，二者直接映射到统一向量空间时容易产生语义损失[4,7]。第二，基础双塔模型虽然具备较高检索效率，但常以全局相似度作为主要排序依据，在对象、关系、人物属性和局部动作等细粒度语义上判别不足[5,9-10]。第三，系统在实际使用中会不断产生失败样本和用户反馈，但如何从这些反馈中筛选高价值监督，并在不破坏已有能力的前提下稳定提升模型性能，仍是持续学习型检索系统的重要难点[16-17]。
```

### 1.2.1 传统视频检索方法研究现状

**建议增补文本**

```text
传统视频检索方法通常依赖人工标注、颜色纹理等低层视觉特征或手工设计的时空特征。这类方法在结构化数据库和特定类别检索中具有一定可解释性，但难以充分表达复杂动作、人物关系和开放语义场景。随着深度学习发展，视频表示逐渐从手工特征过渡到端到端学习特征，检索系统也从关键词匹配转向语义向量匹配。然而，在自然语言查询场景下，仅依赖视觉侧特征仍不足以解决跨模态语义鸿沟问题，因此需要进一步引入文本视频联合建模机制。
```

### 1.2.2 跨模态视频文本检索研究现状

**建议替换/增补文本**

```text
跨模态视频文本检索通常通过视觉编码器和文本编码器分别提取视频与查询表示，并在共享语义空间中计算相似度。双塔结构具有检索效率高、易于大规模索引的优势，因此被广泛应用于文本到视频检索任务。近年来，研究者开始关注双塔模型在细粒度语义对齐上的不足。例如，Holistic Features 说明强全局表征在部分视频检索基准上已经具有较强竞争力[2]，但 TokenBinder、Video-ColBERT 和 VideoComp 等工作进一步指出，仅依赖全局匹配难以稳定区分复杂组合语义和细微时序差异[5,9-10]。因此，如何在保持检索效率的同时引入局部对齐监督，成为视频文本检索的重要研究方向。
```

### 1.2.3 大语言模型增强检索研究现状

**建议替换/增补文本**

```text
大语言模型在检索系统中主要承担查询理解、语义扩展、候选解释和反馈生成等辅助功能。对于自然语言视频检索而言，LLM 可以将短查询或含混查询改写为更明确的语义表达，也可以基于候选视频描述进行二次判断。然而，已有研究也表明，直接将多模态大模型或语言模型用于候选排序可能引入先验偏置和较高推理成本[8]。因此，本文将 LLM 相关模块定位为系统型增强手段，而不是最终主增益来源；真正的核心提升仍应来自文本视频表示空间中的细粒度对齐能力。
```

## 3. 第2章逐节修改

### 2.1.1 文本到视频检索任务定义

**建议增补公式**

```text
给定文本查询集合 Q={q_i}_{i=1}^{N} 与视频集合 V={v_j}_{j=1}^{M}，文本到视频检索的目标是在视频集合中找到与查询 q_i 语义最相关的视频 v_j。设文本编码器为 f_t(·)，视频编码器为 f_v(·)，则二者的相似度可表示为：

s(q_i,v_j)=sim(f_t(q_i),f_v(v_j))

其中 sim(·) 通常采用余弦相似度或归一化点积。系统根据 s(q_i,v_j) 对候选视频排序，并以目标视频在排序列表中的位置评价检索效果。
```

### 2.1.2 视频片段级与视频级检索表示

**建议增补**

```text
在实际系统中，视频通常被划分为多个片段或多帧视角。设视频 v 由 K 个片段表示为 v={c_1,c_2,...,c_K}，每个片段的特征为 h_k=f_v(c_k)。视频级表示可以通过均值池化、最大池化或注意力聚合得到：

z_v = Pool(h_1,h_2,...,h_K)

该表示能够降低检索阶段的存储与计算成本，但也可能压缩局部动作和细粒度关系信息。本文后续引入 multiview features 的原因，正是为了缓解单一视频级向量对局部证据表达不足的问题。
```

### 2.2 视频特征表示相关技术

**建议在 2.2 开头增补**

```text
视频特征表示是自然语言视频检索的基础。与图像不同，视频同时包含空间外观、时间变化和事件结构。若仅从单帧或单一全局向量建模，模型容易忽略动作发生顺序、局部对象变化以及人物属性等信息。因此，视频表示通常需要从片段划分、视觉编码和时序聚合三个层面共同设计。
```

### 2.2.1 视频片段划分方法

**建议替换/增补**

```text
视频片段划分的目标是在计算成本可控的前提下保留足够的时间信息。设原始视频包含 T 帧，可按固定间隔采样得到 K 个片段或关键帧集合：

C(v)=\{x_{t_1},x_{t_2},...,x_{t_K}\}, 1 \leq t_1 < ... < t_K \leq T

固定采样具有实现简单、稳定性好的优点，适合在本地硬件资源有限的条件下完成实验。其不足是对快速动作和短时事件不够敏感，因此本文在后续系统中进一步构建多视角视频特征，用于补充不同时间位置和不同语义侧重点的信息。
```

### 2.2.2 视觉特征提取方法

**建议替换/增补**

```text
视觉特征提取通常依赖预训练视觉语言模型。对于采样得到的片段 x_t，视觉编码器将其映射为 d 维向量：

h_t = f_v(x_t), h_t \in R^d

若模型训练时已经通过大规模图文或视频文本数据完成跨模态对齐，则 h_t 不仅包含低层视觉信息，也具有一定语义可比性。本文使用 ViT-H-14/LAION2B 作为基础编码器，并在后续阶段引入 teacher supervision 和 alignment teacher，使学生表示进一步贴近视频检索任务中的局部语义判别需求。
```

### 2.2.3 时序聚合方法

**建议替换/增补**

```text
时序聚合用于将多个片段特征整合为视频级表示。最常用的均值聚合可表示为：

z_v = \frac{1}{K}\sum_{k=1}^{K} h_k

最大聚合则更强调最显著片段：

z_v^{(m)}=\max_{k=1,...,K}h_k

均值聚合稳定且计算开销低，但可能弱化短时关键动作；最大聚合对显著证据更敏感，但容易受到噪声影响。本文采用均值聚合作为 baseline，并通过 multiview features 在不显著增加在线检索开销的前提下补充多帧和多语义视角信息。
```

### 2.3 向量检索与索引技术

**建议增补**

```text
向量索引的作用是将跨模态相似度计算转化为近似最近邻搜索问题。对于大规模视频库，逐一计算所有视频与查询之间的相似度会带来较高延迟，因此需要借助 FAISS 等向量检索工具构建索引。本文采用向量索引完成初始召回，再在候选集合内进行后续增强，保证整体系统具备可运行性和可扩展性。
```

### 2.4 大语言模型辅助检索相关技术

**建议增补**

```text
大语言模型能够提升检索系统对自然语言表达的理解能力，但其作用应受到任务协议和计算成本约束。对于文本到视频检索，大语言模型适合用于查询改写、语义成分分析和候选解释；若直接用于全库排序，则成本较高且可能产生语言先验偏置。因此，本文采用选择性调用策略，仅在查询存在含混表达或候选差异难以由基础模型区分时引入 LLM 辅助。
```

### 3.3.1 视频片段组织与特征表示

**建议替换/增补**


### 3.4.2 改写生成与语义补充

**建议替换**


**建议替换开头**


### 3.5.1 细粒度对齐问题分析

**建议替换**

```text
在文本到视频检索中，两个候选视频可能具有相似场景和主体，但在动作对象、人物属性或实体关系上存在差异。例如，查询中的“man cutting vegetables”和“person cooking in kitchen”在全局语义上接近，但目标视频可能只对应其中一个具体动作。若模型仅学习全局文本向量与视频向量的相似度，容易把整体相关但局部不匹配的视频排在前面。近年来的细粒度检索研究也指出，token 级交互、组合语义对齐和多视角表示是缓解这一问题的重要方向[5,9-10,13-14]。
```

### 3.5.2 Alignment Teacher 引导的局部对齐学习

**建议替换/增补**

```text
Alignment teacher 的作用是为学生模型提供比全局相似度更细的监督信号。本文将查询语义拆分为动作、对象、场景、关系和人物属性等成分，并利用教师信号评估候选视频局部证据与这些语义成分的一致性。设查询成分集合为 C(q)={c_1,...,c_m}，视频局部证据集合为 E(v)={e_1,...,e_n}，则局部对齐分数可表示为：

a(q,v)=\frac{1}{m}\sum_{i=1}^{m}\max_{j} sim(g_t(c_i),g_v(e_j))

其中 g_t 和 g_v 分别表示语义成分与视频局部证据的表示函数。学生模型不仅学习最终检索分数，也学习该局部对齐趋势，从而减少整体相关但局部错配候选对排序的干扰。
```

### 3.5.3 多视角视频特征增强

**建议替换/增补**

```text
为进一步增强视频侧证据表达，本文构建 multiview features。与单一均值向量不同，多视角特征从不同帧采样、不同局部证据和不同语义属性角度补充视频表示。设视频的多视角表示为 M(v)={m_1,...,m_L}，则学生模型在训练时不仅使用全局视频表示 z_v，也利用多视角证据构成增强表示：

\tilde{z}_v = z_v + \lambda \cdot A(M(v))

其中 A(·) 表示多视角聚合函数，\lambda 为增强权重。该设计的核心目标不是显著增加在线检索复杂度，而是在训练阶段让模型接触更丰富的视频侧证据，从而改善局部语义判别能力。
```

### 3.5.4 表征增强的联合优化目标

**建议替换/增补**

```text
本文的联合优化目标由检索排序损失、教师软标签损失和局部对齐损失组成：

L = L_rank + \beta L_teacher + \gamma L_align + \eta L_mv

其中 L_rank 约束正样本视频相较负样本具有更高相似度；L_teacher 使学生分数接近教师排序分布；L_align 引导学生关注查询语义成分与视频局部证据之间的对应关系；L_mv 则利用多视角特征增强视频侧表示。与单纯 listwise distillation 相比，该目标更强调造成检索错误的局部语义来源，因此更适合改善 R@1 校准问题。
```

**建议替换开头**


### 3.6.1 失败样本诊断与高价值错误筛选

**建议替换/增补**

```text
失败样本并非都具有同等学习价值。若目标视频已经位于 Top-2 或 Top-5，模型可能只需要轻微校准；若目标视频完全不在 Top-30，则说明初始召回存在较大缺陷，直接用于局部排序学习可能引入噪声。本文根据目标视频排名、失败类型和不确定性筛选高价值样本，优先关注“目标视频接近候选前列但未排首位”的 near-failure 样本。这类样本更适合用于学习局部区分边界。
```

### 3.6.2 Feedback Teacher 构建

**建议替换**

```text
Feedback teacher 以失败查询、错误候选和目标视频为输入，生成面向纠错的监督信号。与平均学习全部样本不同，feedback teacher 更关注错误候选与目标视频之间的差异，例如对象是否一致、人物属性是否匹配、动作是否对应以及关系是否正确。该机制的目标是使学生模型学会“为什么目标视频应排在错误候选之前”，而不是简单重复已有 baseline 的排序偏好。
```

**建议替换**

```text

```

### 3.6.4 Acceptance-Gated 晋升机制

**建议替换**

```text
候选模型训练完成后并不会立即替换当前最佳模型，而是需要通过 acceptance-gated 晋升判断。晋升标准以验证集主指标为核心，同时参考 MedR、MnR 和固定参考集表现。若候选模型仅改善辅助损失，或在 locked 参考协议上造成 R@1 下降，则不予晋升。该机制可以降低持续学习中的灾难性遗忘风险，使自学习过程具备可控性。
```
