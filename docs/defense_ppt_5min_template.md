## 第 2 页：研究背景

**页面要点：**

- 视频内容包含人物、动作、对象、场景和关系，比图片更复杂。

**讲解稿：**

## 第 3 页：研究问题与挑战

**页面标题：** 难点：相关视频容易找，最匹配视频难排第一

**页面要点：**

- 基础模型可以召回整体相关视频。
- 但多个候选视频可能场景相似、人物相似、动作相似。
- 真正困难的是 Top-1 排序：谁才是最符合查询细节的视频。

**配图建议：图 3-1 相似候选混淆示意图**

画法：

```text
Query：一个男孩在舞台前唱歌跳舞

候选 A：男孩唱歌跳舞       √ 目标视频
候选 B：多人在舞台唱歌     × 主体不一致
候选 C：男孩在舞台讲话     × 动作不一致
```

**讲解稿：**

这个任务的难点不是“完全找不到相关视频”，而是很多视频看起来都相关。比如都有人、都有舞台、都有动作，但只有一个视频真正同时满足主体、动作和场景。我的工作重点就是提升这种相似候选之间的排序能力。

## 第 5 页：系统基础流程

**页面标题：** 基础检索流程

**页面要点：**

- 视频切分成片段。
- 提取视频特征，建立 FAISS 向量索引。
- 查询文本编码后，与视频向量计算相似度。
- 返回 Top-K 视频结果。

**配图建议：图 5-1 Baseline 检索流程图**

画法：

```text
视频库 → 视频片段化 → 特征提取 → FAISS 索引
                                ↑
文本查询 → 文本编码 → 相似度计算 → Top-K 结果
```

**讲解稿：**

基础流程可以理解为把文字和视频都变成向量。向量越接近，说明语义越相似。为了让检索更快，我使用 FAISS 建立索引，这样系统可以快速从大量视频中找候选。

## 第 7 页：核心创新 1：Alignment Teacher

**页面标题：** 让学生模型知道“该看哪里”

**页面要点：**

- Query 里有动作、对象、关系、人物属性。
- 视频里也有局部帧、局部动作、局部对象。
- Alignment teacher 提供局部对齐监督。

**配图建议：图 7-1 Alignment Teacher 示意图**

画法：

```text
Query 语义成分：
动作 action / 对象 object / 关系 relation / 人物属性 person attribute

            ↓ 对齐监督

视频局部证据：
帧1 / 帧2 / 帧3 / 时间窗口
```

**讲解稿：**

我把 teacher 理解成一个“老师”。它不是只告诉学生模型总分是多少，而是帮助模型理解：文字里的动作、对象、关系，应该和视频里的哪些局部证据对应起来。

---

## 第 8 页：核心创新 2：Multiview Features

**页面标题：** 让视频侧提供更多局部证据

**页面要点：**

- 单一全局向量容易丢失细节。
- 多视角特征包括全局视角、局部帧视角、时间窗视角。
- 查询不同，应该关注的视频视角也不同。

**配图建议：图 8-1 多视角视频表示图**

画法：

```text
同一视频
 ├─ 全局平均视角：整体场景
 ├─ 局部帧视角：对象和人物
 └─ 时间窗视角：动作阶段

Query-aware gate 动态选择视角
```

**讲解稿：**

如果把一个视频压成一个向量，很多细节会被平均掉。所以我构建了多视角视频特征，让模型既能看到整体场景，也能看到局部动作和时间片段。对于动作、关系更复杂的查询，系统会更重视局部视角。

---

## 第 9 页：核心创新 3：错误驱动 Pairwise Teacher

**页面标题：** 从排错的样本里学习

**页面要点：**

- 很多失败不是目标视频没进候选，而是排在第 2-5 名。
- 将正确视频和相似错误候选组成 pair。
- 学习目标：正确视频分数应高于错误候选。

**配图建议：图 9-1 Pairwise Teacher 示意图**

画法：

```text
Query
 ↓
当前排序：错误候选 v- 排第1，正确视频 v+ 排第3
 ↓
Pairwise Teacher：要求 S(q, v+) > S(q, v-)
 ↓
学生模型更新
```

**讲解稿：**

很多错误其实很接近成功，正确视频已经进了候选，只是没排第一。我把这种 near-failure 样本转成成对监督，让模型学习：为什么正确视频应该排在相似错误候选前面。

# 5 分钟答辩完整讲稿（压缩版）

各位老师好，我的毕业论文题目是《基于自然语言查询的视频检索系统设计与实现》。本文研究的问题是：用户输入一句自然语言描述，系统如何从视频库中找到最相关的视频。

随着在线视频数量快速增长，人工标签已经很难覆盖视频中的全部语义。相比关键词检索，用户更希望直接输入一句自然语言，例如“一个人在篮球场投篮”。这就要求系统不仅识别画面，还要理解文字中的动作、对象、场景和关系。

本文关注的核心难点是 Top-1 排序。基础模型通常能召回整体相关的视频，但多个候选视频可能在人物、场景和动作上都很像，系统容易把“看起来相关”的视频排在真正目标视频前面。因此，我的重点是提升相似候选内部的细粒度区分能力。

系统整体采用分层结构。底层是 baseline 检索流程：将视频切分成片段，提取视频特征，使用 FAISS 建立向量索引；输入文本后，系统编码文本并计算相似度，返回 Top-K 视频。除此之外，我还实现了选择性查询改写和候选重排序，用来分析大语言模型在查询补充和语义校准中的作用。实验发现，这些模块对部分查询有效，但不是最终主要增益来源。

本文的核心方法是细粒度表征增强。第一，我引入 alignment teacher，让学生模型知道文字中的动作、对象、关系和人物属性应该对应视频中的哪些局部证据。第二，我构建 multiview features，让视频侧不只依赖单一全局向量，而是同时利用全局视角、局部帧视角和时间窗视角。第三，我设计错误驱动 pairwise teacher，把那些正确视频已经进入候选但没有排第一的 near-failure 样本转成成对监督，让模型学习正确视频为什么应该排在相似错误候选之前。

实验使用 MSR-VTT 数据集。为了避免数据泄露，训练侧使用 safe_train，验证侧使用 safe_dev，最终结果只在 locked 1kA 上报告。评价指标包括 R@1、R@5、R@10、MedR 和 MnR，其中 R@1 是我最关注的首位命中率。

结果显示，本文 Stage4 方法在 full 1kA 上取得了 39.7% 的 R@1，相比上一阶段 38.7% 提升 1.0 个百分点；在 q200 快速验证中，Stage4 augmented adapter 达到 51.0 / 66.0 / 77.0。消融实验也表明，提升主要来自 alignment teacher、多视角特征和 query-aware pairwise teacher 的组合，而不是简单后处理分数融合。

系统实现方面，我完成了前端检索页面，支持用户输入 query 或随机抽取测试 query，结果页可以展示 Top-5 视频和目标视频排名，同时提供历史记录、学习日志和消融图展示。

总结来说，本文完成了一个可运行、可评估、可展示的自然语言视频检索系统，并验证了细粒度对齐增强对提升首位排序能力的作用。不足是，当前方法与强 SOTA 仍有差距，错误驱动自学习闭环还没有稳定超过主模型，后续可以继续增强对象、关系和人物属性等局部语义建模。我的汇报到此结束，谢谢各位老师。
