# 答辩 PPT 核心方法讲解指引：4 个核心贡献 + LLM 辅助模块

> 适用场景：5 分钟毕业答辩 PPT 中的方法部分。  
> 讲解目标：让没有视频检索背景的老师或同学，也能听懂本文到底改进了哪里、为什么这样改、效果如何。  
> 推荐顺序：先讲系统基础流程，再按图中编号依次讲 1-4，最后讲 LLM 重写/重排作为辅助模块。

## 一、总览页：把系统流程讲成“一次找视频的过程”

### PPT 页面标题

系统基础流程与本文优化位置

### 页面应该放什么

使用你现在这张“系统基础流程”图，并保留以下标注：

```text
1. 多视角视频特征
2. alignment teacher + student adapter 表征增强
3. query-aware gate 调节局部/全局权重
4. near-failure pairwise teacher
LLM 重写/重排
```

右侧可以加一个小结果框：

```text
Stage4 q200：
R@1 = 51.0

Stage4 full 1kA：
R@1 = 39.7
```

### 要讲清楚什么

这一页不展开算法，只让听众知道：系统先把视频和文字都变成向量，然后比较相似度，最后返回 Top-K 视频。本文创新不是重做整个系统，而是在几个关键环节提高“看细节”和“排第一”的能力。

### 面向中学生的解释

可以这样讲：

> 可以把这个系统理解成“用一句话去视频库里找视频”。系统先把每个视频变成一串数字，也把用户输入的文字变成一串数字。两串数字越接近，说明文字和视频越匹配。本文做的改进，就是让这些数字不仅能表示大概内容，还能表示动作、对象、关系这些细节。

### 讲解稿

这张图展示的是系统基础流程。上面是视频侧，视频先被切成片段，然后提取特征并建立 FAISS 索引；下面是文本侧，用户输入查询后，系统对文本编码，再和视频向量做相似度计算，最后返回 Top-K 结果。本文的核心工作主要插入在四个位置：视频特征提取之后、文本表征增强阶段、相似度计算阶段，以及离线训练阶段。同时，LLM 重写和重排作为辅助模块，用来处理部分表达不清或候选很接近的查询。

## 二、核心贡献 1：多视角视频特征

### PPT 页面标题

贡献 1：让模型从多个角度看同一个视频

### 页面应该放什么

建议画一张简单的“三视角”图：

```text
同一段视频
 ├─ 全局视角：整体场景是什么？
 ├─ 局部帧视角：画面里有哪些人和物？
 └─ 时间窗视角：动作发生在哪个阶段？
```

中间放一个视频小图标，向右分出三条支路：

```text
视频 → 全局特征
视频 → 局部帧特征
视频 → 时间窗口特征
```

底部写一句：

```text
目的：减少单一全局向量丢失细节的问题
```

### 要讲清楚什么

传统 baseline 通常把视频压缩成一个整体向量。这样做效率高，但容易把局部动作、人物属性、小物体、短时间事件平均掉。多视角视频特征就是让模型同时看到“整体”和“细节”。

### 面向中学生的解释

可以用“看电影写观后感”的类比：

> 如果只让你用一句话概括一部电影，你可能会说“这是一个篮球视频”。但如果老师问“有没有投篮动作”“球是不是进了篮筐”“是谁在投”，一句概括就不够了。多视角特征就像同时看剧情简介、关键截图和动作片段，让模型不只知道大概场景，还能看到关键细节。

### 与流程图的位置关系

在图中，它位于：

```text
视频片段化 → 特征提取
```

也就是视频特征提取阶段的增强。它不是在线重新看完整视频，而是在离线阶段提前构建更丰富的视频表示。

### 可以写在 PPT 上的短句

```text
多视角视频特征：
从“一个全局向量”扩展为“全局 + 局部帧 + 时间窗”表示。
```

### 讲解稿

第一个贡献是多视角视频特征。原始方法通常把一个视频表示成一个整体向量，这样检索很快，但容易丢失细节。比如视频整体是篮球场景，但真正重要的可能是“投篮”这个动作，或者人物和球之间的关系。本文构建了多视角视频特征，让模型同时利用整体场景、局部帧和时间窗口信息。这样做的目的，是让视频侧提供更多可用于匹配查询的局部证据。

### 老师可能问什么

**问：多视角是不是只是多提几帧？**

答：

> 不完全是。单纯多提帧只是增加数量，而本文强调不同视角的互补性：全局视角负责整体语义，局部帧视角负责对象和人物，时间窗视角负责动作阶段。

## 多视角视频特征增强公式

首先，将视频 \(v\) 表示为多个互补视角：

\[ M(v)=\{m_1,m_2,\cdots,m_K\} \]

其中，\(m_k\) 表示第 \(k\) 个视频视角特征。在本文中，这些视角主要包括：

\[ m_k \in \{m_{\mathrm{global}}, m_{\mathrm{frame}}, m_{\mathrm{window}}\} \]

即：

- \(m_{\mathrm{global}}\)：全局视频表示，用于描述整体场景；
- \(m_{\mathrm{frame}}\)：局部帧表示，用于捕捉人物、对象和局部动作；
- \(m_{\mathrm{window}}\)：时间窗口表示，用于表示动作或事件的不同阶段。

------

对于给定查询 \(q\)，先计算它与每个视频视角之间的匹配分数：

\[ s_k(q,v)=\mathrm{sim}(q,m_k) \]

其中，\(\mathrm{sim}(\cdot)\) 表示余弦相似度或归一化点积。

------

随后，通过 softmax 得到不同视角的重要性权重：

\[ \beta_k(q,v)= \frac{\exp(s_k(q,v)/\tau)} {\sum_{j=1}^{K}\exp(s_j(q,v)/\tau)} \]

其中，\(\tau\) 为温度系数，用来控制权重分布的平滑程度。若某个视角与当前查询更相关，它的 \(\beta_k\) 就会更大。

------

最终，多视角匹配分数定义为：

\[ S_{\mathrm{mv}}(q,v)= \sum_{k=1}^{K}\beta_k(q,v)s_k(q,v) \]

也就是说，系统不是简单平均多个视角，而是根据 query 动态选择更重要的视频证据。

------

最后，将全局匹配分数和多视角匹配分数融合：

\[ S_{\mathrm{final}}(q,v)= S_{\mathrm{global}}(q,v)+ \lambda_{\mathrm{mv}}\alpha(q)S_{\mathrm{mv}}(q,v) \]

其中：

- \(S_{\mathrm{global}}(q,v)\)：基础全局相似度；
- \(S_{\mathrm{mv}}(q,v)\)：多视角局部匹配分数；
- \(\lambda_{\mathrm{mv}}\)：多视角特征权重；
- \(\alpha(q)\)：query-aware gate，根据查询复杂度调整局部证据的重要性。

\[ M(v)=\{m_{\mathrm{global}},m_{\mathrm{frame}},m_{\mathrm{window}}\} \] \[ S_{\mathrm{mv}}(q,v)= \sum_{k=1}^{K} \mathrm{softmax}\left(\frac{\mathrm{sim}(q,m_k)}{\tau}\right) \mathrm{sim}(q,m_k) \]

## 三、核心贡献 2：Alignment Teacher + Student Adapter 表征增强

### PPT 页面标题

贡献 2：用教师监督教模型关注局部语义

### 页面应该放什么

建议画成“老师教学生”的结构：

```text
Query：a man throwing a ball to the basket

语义成分：
动作：throwing
对象：ball / basket
主体：man
关系：ball → basket

          ↓ alignment teacher

student adapter 学习更好的文本-视频表示
```

可以用两个小框：

```text
Teacher：提供局部对齐监督
Student：学习轻量 adapter
```

### 要讲清楚什么

Teacher 的作用不是在线替系统检索，而是在训练阶段提供“指导信号”。Student adapter 是真正部署时使用的轻量模型，它学习 teacher 给出的局部对齐知识。

### 面向中学生的解释

可以用“老师批改作文”的类比：

> 学生一开始只知道这篇作文大概写得对不对，但老师会指出：这里动作写错了，这里对象没对上，这里人物关系不准确。学生被这样训练之后，下次就更知道该看哪些细节。

### 与流程图的位置关系

在图中，它位于：

```text
文本编码 → 相似度计算
```

之间的表征增强位置。严格来说，alignment teacher 主要在离线训练阶段使用，训练出来的 student adapter 再用于在线检索。

### 可以写在 PPT 上的短句

```text
Alignment Teacher：
教 student adapter 学习 query 语义成分与视频局部证据的对应关系。
```

### 讲解稿

第二个贡献是 alignment teacher 和 student adapter。这里的 teacher 可以理解成训练阶段的老师，它帮助模型判断查询中的动作、对象、关系和人物属性，应该与视频中的哪些局部证据对应。student adapter 则是实际部署时使用的轻量模块。通过这种方式，模型不只是学习“这段文字和这个视频像不像”，而是进一步学习“为什么这个视频和这段文字匹配”。

### 老师可能问什么

**问：Teacher 会不会增加在线检索时间？**

答：

> 主要不会。Teacher 主要用于离线训练，在线检索时使用的是训练后的 student adapter。这样可以把较强 teacher 的知识压缩到轻量学生模型中，避免在线阶段成本过高。

### 1. 查询拆分

\[ C(q)=\{c_{\mathrm{act}},c_{\mathrm{obj}},c_{\mathrm{rel}},c_{\mathrm{attr}},c_{\mathrm{scene}}\} \]

含义：把 query 拆成动作、对象、关系、人物属性和场景。

------

### 2. 局部对齐分数

\[ A_{i,t}=\mathrm{sim}(c_i,l_t) \]

含义：计算第 \(i\) 个文本语义成分和第 \(t\) 个视频局部证据是否匹配。

------

### 3. Student Adapter 表征增强

\[ \tilde{q}=q+\gamma f_{\theta}(q) \]

含义：adapter 在原始文本表示上学习一个轻量修正，使文本表示更适合检索视频。

------

### 4. 对齐监督损失

\[ \mathcal{L}_{align} = \|A^S(q,v)-A^T(q,v)\|^2 \]

含义：让 student 预测的对齐关系接近 teacher 给出的对齐关系。

## 四、核心贡献 3：Query-aware Gate 调节局部/全局权重

### PPT 页面标题

贡献 3：不同查询使用不同视频证据

### 页面应该放什么

建议画两个查询对比：

```text
简单查询：a beach scene
→ 更依赖全局场景特征

复杂查询：a boy throws a ball into a basket
→ 更依赖局部动作和对象关系
```

中间画一个 gate：

```text
query-aware gate
判断 query 类型
调节全局 / 局部权重
```

### 要讲清楚什么

不同 query 对视频证据的需求不同。简单场景查询，整体向量就够了；复杂动作或关系查询，需要更多局部帧和时间窗信息。query-aware gate 就是动态调整权重。

### 面向中学生的解释

可以用“找东西”的类比：

> 如果我要找“操场”，只看整体画面就够了；如果我要找“一个男孩把球投进篮筐”，就不能只看操场，还要看男孩、球、篮筐和动作顺序。query-aware gate 就像一个开关，判断这次搜索应该更看整体，还是更看细节。

### 与流程图的位置关系

在图中，它位于：

```text
相似度计算
```

旁边。因为它决定最终计算相似度时，全局特征和局部多视角特征各占多少权重。

### 可以写在 PPT 上的短句

```text
Query-aware Gate：
简单查询偏全局，复杂查询偏局部。
```

### 讲解稿

第三个贡献是 query-aware gate。不同查询需要的视频证据不同。如果查询只是“海边场景”，全局场景特征已经比较够用；但如果查询是“一个男孩把球投向篮筐”，模型必须关注人物、球、篮筐和动作阶段。query-aware gate 的作用就是根据查询类型，动态调节全局特征和局部多视角特征的权重。

### 老师可能问什么

**问：为什么不一直使用局部特征？**

答：

> 因为局部特征并不总是有益。对于简单场景查询，过多局部信息可能引入噪声；对于复杂动作和关系查询，局部信息才更重要。因此需要 query-aware gate 做动态调节。

## 五、核心贡献 4：Near-failure Pairwise Teacher

### PPT 页面标题

贡献 4：从“差一点排对”的错误中学习

### 页面应该放什么

建议画一个排序列表：

```text
Query：a man throwing a ball to the basket

当前排序：
1. 相似错误视频 v-
2. 其他候选
3. 正确视频 v+

学习目标：
S(query, v+) > S(query, v-)
```

底部写一句：

```text
专门学习 Top-1 排序边界
```

### 要讲清楚什么

near-failure 指的是“正确视频已经进候选了，但没有排第一”。这类样本最适合训练排序，因为模型已经快做对了，只差把相似错误候选区分开。

### 面向中学生的解释

可以用考试错题本类比：

> 如果一道题完全不会，马上纠正很难；但如果只差一步做错了，这类错题最值得整理。near-failure 就是模型的“错题本”，pairwise teacher 让模型学习为什么正确答案应该排在错误答案前面。

### 与流程图的位置关系

在图中，它是底部离线训练支路：

```text
离线训练支路：near-failure pairwise teacher
```

它不是用户搜索时临时运行，而是训练前或训练中构造监督信号，用来优化 student adapter 的排序能力。

### 可以写在 PPT 上的短句

```text
Near-failure Pairwise Teacher：
把“正确视频排在相似错误候选后面”的失败样本转成排序监督。
```

### 讲解稿

第四个贡献是 near-failure pairwise teacher。很多失败样本并不是完全找不到正确视频，而是正确视频已经排在第二、第三或第五名，只是没有排第一。这类样本最有学习价值，因为模型已经接近正确，只需要学会区分正确视频和相似错误候选。本文把它构造成成对监督，要求正确视频的分数高于相似错误视频，从而提升 Top-1 排序能力。

### 老师可能问什么

**问：为什么不学习所有错误样本？**

答：

> 不是所有错误都有价值。如果正确视频根本没进候选，可能是召回层问题，直接拿来训练排序会引入噪声。near-failure 样本更接近排序校准问题，因此更适合 pairwise teacher 学习。

# 页面右侧：核心公式

## 1. Near-failure 样本定义

设目标视频在当前排序中的名次为：

\[ r(q,v^+) \]

当：

\[ 1 < r(q,v^+) \leq K_f \]

时，该样本被视为 near-failure 样本。

其中：

| 符号         | 含义                               |
| ------------ | ---------------------------------- |
| \(v^+\)      | 正确视频                           |
| \(r(q,v^+)\) | 正确视频在检索结果中的排名         |
| \(K_f\)      | near-failure 筛选范围，例如 Top-30 |

含义：

text



```
正确视频进了候选，但没排第一。 
```

------

## 2. 相似错误候选

从排在正确视频前面的候选中选取错误视频：

\[ v^- \in \{v \mid r(q,v) < r(q,v^+), v \neq v^+\} \]

也就是：

text



```
当前排在正确视频前面的相似错误候选。 
```

------

## 3. Pairwise 排序损失

训练目标是让正确视频得分高于错误候选：

\[ S(q,v^+) > S(q,v^-) \]

对应损失函数为：

\[ \mathcal{L}_{pair} = \max \left(0,\ m - S(q,v^+) + S(q,v^-)\right) \]

其中：

| 符号                   | 含义                     |
| ---------------------- | ------------------------ |
| \(S(q,v^+)\)           | query 与正确视频的相似度 |
| \(S(q,v^-)\)           | query 与错误候选的相似度 |
| \(m\)                  | 间隔 margin              |
| \(\mathcal{L}_{pair}\) | 成对排序损失             |

## 六、辅助模块：LLM 重写 / 重排

### PPT 页面标题

辅助模块：LLM 用于查询补充和候选语义判断

### 页面应该放什么

建议画两个小流程：

```text
查询改写：
原始 Query → 歧义检测 → LLM 改写 → 检索

候选重排：
Top-5 候选 → LLM 语义比较 → 调整排序
```

右侧放一句结论：

```text
有局部收益，但不是主增益来源
```

### 要讲清楚什么

LLM 可以帮助处理语义不清的查询，也可以辅助判断少量候选。但是它的成本高、延迟高，并且可能引入语义漂移。所以本文把它作为辅助模块，而不是最终主方法。

### 面向中学生的解释

可以这样讲：

> 如果用户只输入“有人在玩”，系统不知道是玩游戏、玩球还是玩乐器，这时候 LLM 可以帮忙把话说清楚。但如果原句已经很清楚，LLM 再改写反而可能越改越啰嗦，甚至偏离原意。

### 与流程图的位置关系

在图中，LLM 重写/重排位于：

```text
文本查询之前 / Top-K 候选之后
```

更准确地说：

- Rewrite：在文本编码前，优化输入 query。
- Rerank：在初步召回后，对少量候选重新排序。

### 可以写在 PPT 上的短句

```text
LLM 辅助：
适合含混查询和少量候选分析，但成本较高，不作为主增益来源。
```

### 讲解稿

除了四个核心贡献，本文还实现了 LLM 重写和重排。查询改写用于处理表达较短或含混的输入，候选重排用于对 Top-5 结果做语义比较。实验发现，这些模块对部分查询有效，但由于 MSR-VTT 的很多查询本身已经比较清晰，加上 LLM 调用成本和延迟较高，所以它更适合作为辅助功能，而不是最终主增益来源。

### 老师可能问什么

**问：为什么不用 LLM 直接做最终检索？**

答：

> 因为视频库规模一大，让 LLM 对所有视频逐个判断成本太高，也不适合实时检索。本文使用 LLM 做小范围辅助，把主要性能提升放在轻量检索模型本身。

## 七、五个方法之间的逻辑关系

### PPT 页面标题

五个模块不是堆叠，而是分工明确

### 页面应该放什么

建议画一个三层结构：

```text
视频表示层：
多视角视频特征

表征学习层：
alignment teacher + student adapter

排序校准层：
query-aware gate + near-failure pairwise teacher

系统辅助层：
LLM rewrite / rerank
```

### 要讲清楚什么

这五个方法不是互相重复，而是分别解决不同问题：

| 模块 | 解决的问题 | 是否主贡献 |
|---|---|---|
| 多视角视频特征 | 视频侧细节不够 | 是 |
| alignment teacher + adapter | 文本和视频局部证据对不准 | 是 |
| query-aware gate | 不同查询需要不同证据 | 是 |
| near-failure pairwise teacher | 相似候选排错 | 是 |
| LLM rewrite / rerank | 查询表达不足、候选语义辅助 | 辅助 |

### 讲解稿

这几个模块不是简单堆起来的。多视角视频特征解决视频侧证据不够的问题；alignment teacher 解决文本和视频局部语义对不准的问题；query-aware gate 解决不同查询使用同一套权重的问题；near-failure pairwise teacher 解决相似候选排错的问题。LLM 重写和重排则是辅助模块，主要用于查询不清楚或候选很接近的情况。

## 八、建议在 5 分钟答辩中的压缩讲法

如果时间只有 5 分钟，方法部分不要逐字展开，可以这样讲：

> 本文的核心创新主要有四点。第一，在视频侧构建多视角视频特征，让模型不仅看到整体场景，也能看到局部帧和时间窗口中的细节。第二，引入 alignment teacher 和 student adapter，让学生模型学习查询中的动作、对象、关系和人物属性如何对应到视频局部证据。第三，设计 query-aware gate，根据查询类型动态调节全局特征和局部特征的权重。第四，利用 near-failure pairwise teacher，从“正确视频已经进入候选但没有排第一”的样本中学习排序边界。除此之外，本文还实现了 LLM 查询改写和候选重排，用作系统辅助模块，但最终主增益主要来自细粒度表征增强。

## 九、PPT 视觉设计建议

### 配色

建议沿用你当前图中的风格：

- 主流程：白底黑线框。
- 核心贡献：蓝紫渐变气泡。
- 辅助模块：浅蓝气泡。
- 离线训练支路：紫色长条。
- 结果框：浅绿色或浅橙色。

### 字体

建议：

- 标题：微软雅黑 / 黑体。
- 正文：微软雅黑。
- 图内文字：微软雅黑或宋体。
- 每个框内不超过两行。

### 每页文字数量

方法页每页最多：

```text
标题 1 行
核心图 1 张
解释文字 2-3 条
结果或结论 1 行
```

### 不建议出现的写法

不要写：

```text
本文通过构建复杂多模态系统综合提升语义理解能力
```

建议写：

```text
让模型看更多视频细节，并学会把正确视频排到相似错误视频前面
```

这样老师更容易立刻理解。
