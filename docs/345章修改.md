# 第3章 基于细粒度对齐增强的自然语言视频检索方法

本章在前文相关理论的基础上，进一步给出本文自然语言视频检索方法的具体设计。与仅完成检索系统搭建不同，本文关注的核心问题是：在保证系统能够高效完成候选召回的前提下，如何进一步提升目标视频在相似候选集合中的首位排序能力。为此，本文首先构建基于预训练视觉语言模型和向量索引的基线检索流程；随后分析查询改写和候选重排序在系统层面的辅助作用；在此基础上，重点提出 alignment teacher 与 multiview features 相结合的细粒度表征增强方法，使学生检索模型能够学习查询语义成分与视频局部证据之间的对应关系。最后，本文进一步设计错误驱动反馈学习机制，用于探索检索系统从失败样本中持续吸收监督信号的可能性。

## 3.1 方法设计目标与总体框架

### 3.1.1 问题定义与任务设定

自然语言视频检索任务可以描述为：给定一个文本查询 \(q\) 和视频库 \(\mathcal{V}=\{v_1,v_2,\ldots,v_N\}\)，系统需要根据查询语义对视频库中的候选视频进行排序，并返回与查询最相关的视频结果。设检索模型对查询 \(q\) 与视频 \(v_i\) 的匹配分数为 \(S(q,v_i)\)，则文本到视频检索的目标可以表示为：

\[
\operatorname{rank}(q)=\operatorname{argsort}_{v_i\in \mathcal{V}}S(q,v_i)
\tag{3-1}
\]

其中，\(S(q,v_i)\) 越大，表示视频 \(v_i\) 与查询 \(q\) 的语义相关性越高。实际检索系统不仅要求排序结果准确，还要求在较大视频库中保持较低响应时间。因此，本文采用高效双塔式视觉语言编码器作为基础召回模型，并利用 FAISS 构建向量索引，以降低在线检索阶段的计算开销。

与图像文本检索相比，文本到视频检索面临更复杂的语义对齐问题。一个视频通常包含多个时间片段、多个动作阶段和多个局部视觉对象；一个自然语言查询也可能同时涉及人物、动作、对象、场景、关系和属性等语义成分。若仅将整句文本和整段视频压缩为单一全局向量，模型虽然能够判断二者是否整体相关，却可能无法稳定区分多个相似候选之间的细微差异。近年来关于细粒度视频文本检索的研究也指出，复杂视频检索的瓶颈往往不在于粗粒度相关性判断，而在于局部语义、组合关系和时间证据是否能够被准确建模[R1][R2]。

因此，本文将研究目标限定为：在保持高效候选召回能力的基础上，进一步提升目标视频在候选集合中的首位排序能力。换言之，本文并不单纯追求扩大候选范围，而是重点解决“目标视频已经进入候选集合，但排序仍不够靠前”的问题。该目标与本文后续提出的 alignment teacher 和 multiview features 具有直接关系：前者提供局部对齐监督，后者增强视频侧多视角证据表示，两者共同服务于候选内部排序校准。

### 3.1.2 方法设计原则

本文方法设计遵循三个原则。第一，保持检索底座的高效性。自然语言视频检索系统需要在用户提交查询后快速返回结果，因此本文没有采用全量视频交叉编码的方式，而是保留双塔式文本编码器和视频编码器，将视频特征离线提取并存入向量索引。该设计能够将在线计算主要限制在文本编码、向量检索和视频级聚合阶段，适合作为本地单机环境下的检索底座。

第二，增强局部语义对齐能力。基础双塔模型通常依赖全局向量相似度进行排序，在多个候选视频整体相关但局部细节不同的情况下，容易出现 Top-1 排序错误。为解决这一问题，本文在训练阶段引入 alignment teacher，对查询中的动作、对象、场景、关系和人物属性等语义成分提供局部监督。同时，本文构建多视角视频特征，使视频侧表示不再仅依赖单一全局向量，而能够包含多帧、多片段和多时间窗信息。

第三，严格区分训练、验证和最终报告协议。本文使用 MSR-VTT train 9k 安全子集构建 teacher supervision 和 feedback memory，使用 safe_dev 进行候选模型选择，locked 1kA 仅用于固定报告和最终结果分析。该设计可以避免将测试集标注信息用于训练或持续学习，降低数据泄露风险，并保证实验结论具有较好的可信度。

### 3.1.3 分层检索框架

本文整体方法采用分层结构，如图3-1所示。第一层为基础候选召回层，负责将自然语言查询编码为文本向量，并通过 FAISS 向量索引从视频库中快速召回候选视频。第二层为系统型候选优化层，包括选择性查询改写和候选重排序，用于分析大语言模型在查询补充和候选判断中的辅助价值。第三层为细粒度表征增强层，也是本文的核心方法部分，主要包括 alignment teacher、多视角视频特征和学生检索模型训练。该层的目标不是简单改变最终分数，而是通过训练过程改善学生模型的跨模态表示空间。

### 3.1.4 本文方法贡献定位

本文的核心方法贡献可以概括为“面向自然语言视频检索的细粒度对齐增强”。具体而言，本文通过 alignment teacher 为学生检索模型提供局部语义监督，使模型不只学习查询和视频整体是否相关，还学习动作、对象、人物属性和关系等局部证据是否对应；同时，本文通过 multiview features 增强视频侧表示，使视频不再仅由单一全局向量表达，而是由多个时间和语义视角共同提供匹配证据。

这一设计与简单后处理分数融合有本质区别。若仅在检索结果后端对多个分数进行线性融合，系统只能改变最终排序分数，而无法改变学生模型内部的表示能力。本文实验表明，当前最佳结果来自 adapter 方法，而不是 fused score，这说明性能增益主要来自学生模型表征空间的改善。换言之，本文主方法的价值不在于叠加更多后处理模块，而在于通过细粒度监督让检索模型自身具备更强的候选区分能力。

## 3.2 基础召回与系统型候选优化

### 3.2.1 视频片段化与基础向量召回

为了使视频库能够被高效检索，本文首先对原始视频及其标注信息进行统一整理，生成包含视频编号、片段路径、查询标注和数据划分信息的 manifest 文件。视频片段化的目的在于将原始视频转化为适合视觉语言编码器处理的基本单元，同时保留视频级标识，便于后续将片段级检索结果聚合为视频级排序结果。

设视频 \(v\) 被划分为 \(n\) 个片段，记为 \(v=\{s_1,s_2,\ldots,s_n\}\)。本文使用预训练视觉语言模型对每个片段进行编码，得到片段级视觉特征：

\[
z_i=f_v(s_i),\quad i=1,2,\ldots,n
\tag{3-2}
\]

其中，\(f_v(\cdot)\) 表示视频侧编码器，\(z_i\) 表示第 \(i\) 个视频片段的向量表示。所有视频特征均在离线阶段完成提取并持久化保存，在线检索阶段只需对输入文本进行编码并执行向量搜索，从而降低系统响应时间。

对于输入查询 \(q\)，文本编码器生成查询向量：

\[
t=f_t(q)
\tag{3-3}
\]

基础检索阶段通过计算文本向量与视频级表示之间的余弦相似度得到匹配分数：

\[
S(q,v)=\cos(t,\bar{z}_v)=\frac{t^\top \bar{z}_v}{\|t\|\|\bar{z}_v\|}
\tag{3-4}
\]

其中，\(\bar{z}_v\) 表示视频级聚合表示。本文采用 mean pooling 得到视频级表示：

\[
\bar{z}_v=\frac{1}{n}\sum_{i=1}^{n}z_i
\tag{3-5}
\]

mean pooling 能够稳定整合多个片段的信息，适合作为高效检索底座。相比之下，max pooling 更强调局部显著片段，可能放大噪声片段对最终排序的影响。本文在后续消融实验中进一步验证了 mean pooling 的优势，因此将其作为全文主实验设置。

### 3.2.2 候选范围与视频级聚合

基础召回层的主要任务是保证目标视频尽可能进入候选集合。若目标视频在 Top-K 召回阶段已经缺失，则后续查询改写、候选重排序、细粒度对齐或反馈学习都难以直接修正该样本。因此，本文首先保证候选召回层的稳定性，再研究候选内部排序校准问题。

不过，候选召回能力并不等同于最终检索精度。当 Top-K 候选已经覆盖较多目标视频时，继续扩大候选范围会增加索引搜索、缓存和 teacher 构建成本，但不一定显著提升 Top-1。本文在 3.6 节中通过候选召回曲线说明，Top-30 之后边际收益开始变缓，因此后续增强主要围绕“目标视频已进入候选集合但排序仍不够靠前”的情况展开。

### 3.2.3 选择性查询改写

自然语言查询可能存在语义省略、主体不明确或动作对象缺失等问题。对于这类查询，直接使用原始文本编码可能导致文本向量无法充分表达用户意图。本文设计选择性查询改写机制，先判断查询是否缺少关键语义成分，再决定是否调用大语言模型进行语义补充。

设原始查询为 \(q\)，歧义检测函数为 \(A(q)\)，阈值为 \(\tau\)，则选择性改写过程可以表示为：

\[
q'=
\begin{cases}
g(q), & A(q)>\tau\\
q, & A(q)\leq \tau
\end{cases}
\tag{3-6}
\]

其中，\(g(\cdot)\) 表示大语言模型生成的改写函数。该策略的重点不是改变原始查询意图，而是在查询表达不足时补充动作、对象、场景或关系约束。实验结果表明，rewrite 对部分含混查询有效，但由于 MSR-VTT 中大量查询本身较清晰，全量改写并不能稳定带来主结果提升。因此，本文将 rewrite 作为系统型辅助模块，并在第5章中结合查询清晰度诊断分析其适用边界。

### 3.2.4 候选重排序

候选重排序模块用于在基础召回结果的局部范围内进一步比较查询与候选视频之间的语义一致性。系统首先从基础召回结果中选取 Top-N 候选，再利用候选语义信息和查询描述进行重新评分。候选重排序的形式可以写为：

\[
\hat{S}(q,v_i)=\alpha S(q,v_i)+(1-\alpha)R(q,v_i)
\tag{3-7}
\]

其中，\(S(q,v_i)\) 表示基础检索相似度，\(R(q,v_i)\) 表示重排序模块给出的语义匹配评分，\(\alpha\) 表示融合权重。该模块能够在部分案例中修正基础排序，但其效果依赖候选语义描述质量和大语言模型判断能力，同时会引入额外推理成本。

因此，本文将查询改写和候选重排序定位为“系统型候选优化”而不是核心算法贡献。它们用于验证检索流程中前处理和后处理的增益边界，而本文真正的主方法仍是后续 alignment teacher 与 multiview features 所构成的细粒度表征增强。

## 3.4 Alignment Teacher 细粒度对齐监督

### 3.4.1 设计动机

基础双塔检索模型通常通过一个全局相似度分数衡量文本与视频的相关性。当查询与候选视频在整体场景上相似时，这种方式容易产生排序混淆。例如，两个候选视频都包含人物和室内场景，但只有一个视频真正满足查询中的具体动作或对象关系；又如，多个运动视频都具有相似背景，但目标视频中的人物属性或动作对象才是区分关键。此类错误说明，全局向量匹配难以充分表达局部语义证据。

Alignment teacher 的作用在于为学生模型提供更明确的局部监督。它不直接替代检索模型，也不在在线阶段对全库视频进行高成本重排，而是在训练阶段提供查询语义成分与视频局部证据之间的对齐信号。通过这种方式，学生模型能够在保持高效双塔检索结构的同时，获得更强的细粒度候选区分能力。

### 3.4.2 查询语义成分分解

本文将查询语义拆分为动作、对象、场景、关系和人物属性等成分。这种划分并非任意设定，而是来源于自然语言视频检索中的常见错误类型。对于复杂查询而言，模型不仅需要判断视频是否包含相似场景，还需要判断动作是否一致、对象是否正确、人物属性是否匹配，以及不同实体之间的关系是否符合文本描述。

设查询 \(q\) 的语义成分集合为：

\[
C(q)=\{c_{act},c_{obj},c_{scene},c_{rel},c_{attr}\}
\tag{3-6}
\]

其中，\(c_{act}\)、\(c_{obj}\)、\(c_{scene}\)、\(c_{rel}\)、\(c_{attr}\) 分别表示动作、对象、场景、关系和属性成分。对于缺失某类语义的查询，对应成分可以为空。通过显式表示这些成分，teacher 可以更有针对性地判断视频是否包含相应局部证据。

### 3.4.3 视频局部证据构建

为了与查询语义成分进行对齐，本文从视频侧构建局部证据表示。视频局部证据主要来自多帧特征、多片段特征和不同时间窗口的表示。与单一全局向量相比，这些局部证据能够更好地保留动作阶段、对象出现位置和局部场景变化信息。

设视频 \(v\) 的局部证据集合为：

\[
E(v)=\{e_1,e_2,\ldots,e_M\}
\tag{3-7}
\]

其中，\(e_j\) 表示视频中的第 \(j\) 个局部证据向量。Alignment teacher 根据查询成分 \(C(q)\) 与视频证据 \(E(v)\) 之间的匹配程度生成对齐监督。该过程避免了在线阶段对全库视频执行复杂交叉编码，而是将较高成本的细粒度判断转移到训练阶段完成。

### 3.4.4 教师软标签与排序偏好

Alignment teacher 为候选集合提供两类监督信号：一类是候选级软标签，用于约束学生模型学习 teacher 对候选相关性的整体判断；另一类是局部排序偏好，用于强调目标视频应当排在相似但错误的 hard negative 之前。设 teacher 和 student 在候选集合 \(V_i\) 上产生的概率分布分别为 \(P_T(q_i,V_i)\) 和 \(P_S(q_i,V_i)\)，则教师蒸馏损失可以写为：

\[
\mathcal{L}_{teacher}=\sum_i \mathrm{KL}(P_T(q_i,V_i)\|P_S(q_i,V_i))
\tag{3-8}
\]

其中，\(\mathrm{KL}(\cdot)\) 表示 KL 散度。该损失使学生模型在候选排序分布上接近 teacher 的判断，而不是只学习一个硬标签。

对于目标视频 \(v^+\) 和高相似错误候选 \(v^-\)，本文进一步引入 pairwise ranking 约束：

\[
\mathcal{L}_{pair}=\max(0,m-S(q,v^+)+S(q,v^-))
\tag{3-9}
\]

其中，\(m\) 为间隔超参数。该损失要求目标视频得分至少高于错误候选一定间隔，能够直接作用于 Top-1 排序校准。相比随机负样本，高相似错误候选更接近真实检索瓶颈，因此对提升候选内部判别能力更有价值。

### 3.4.5 Alignment Teacher 的作用分析

从实验过程看，单纯依靠基础召回模型时，系统在 q200 评测中的 R@1 为 47.5；引入 alignment teacher 后，adapter 的 R@1 提升到 49.0；进一步加入门控校准后，R@1 提升到 49.5；在引入教师目标集合后，R@1 达到 50.0。这一链路说明，局部对齐监督确实能够逐步改善首位排序能力。

需要注意的是，alignment teacher 的价值不应理解为“增加一个额外 loss”这么简单。它的核心作用是改变学生模型所接收的监督粒度：从只判断视频整体是否相关，转向学习查询语义成分与视频局部证据之间的对应关系。该设计与近年来细粒度视频文本对齐、组合语义理解和 token-wise interaction 的研究趋势一致[R1][R2][R3]。

## 3.5 多视角视频特征增强

### 3.5.1 设计动机

视频内容具有明显的时间连续性和局部变化特征。若仅使用单一全局向量表示整个视频，模型可能获得较稳定的整体语义，但会损失局部动作、短时对象和细微关系信息。对于自然语言视频检索而言，这些局部信息往往正是区分相似候选的关键。

因此，本文在 alignment teacher 的基础上进一步构建 multiview features。该模块从多个时间窗口和多个帧组合中提取视频表示，使学生模型能够同时利用全局语义和局部证据。与简单增加视频帧数不同，多视角特征强调不同视角之间的互补性：全局视角提供稳定场景信息，局部视角提供动作和对象证据，时间窗口视角提供事件阶段信息。

### 3.5.2 多帧与多时间窗表示

设视频 \(v\) 的多视角表示为：

\[
M(v)=\{m_1,m_2,\ldots,m_K\}
\tag{3-10}
\]

其中，\(m_k\) 表示第 \(k\) 个视频视角特征。本文构建的视角包括全局帧均值、局部片段表示和多时间窗表示。全局帧均值用于保持视频整体语义稳定，局部片段表示用于捕捉短时动作和对象，多时间窗表示用于覆盖视频中的不同事件阶段。

通过这种方式，视频侧表示不再是单一路径，而是由多个互补视角共同构成。对于包含复杂动作、对象关系或人物属性的查询，模型可以从更细的视频证据中寻找匹配线索，从而缓解全局表示过度压缩带来的信息损失。

### 3.5.3 查询感知的视角匹配

不同查询对视频证据的需求并不相同。对于简单场景查询，全局视频表示往往已经足够；而对于包含动作、关系和人物属性的查询，局部视角的重要性更高。因此，本文引入查询感知的视角匹配思想，根据查询语义复杂度动态调整全局相似度和局部相似度的权重。

查询感知融合可以表示为：

\[
S_{final}(q,v)=(1-\alpha_q)S_{global}(q,v)+\alpha_q S_{local}(q,v)
\tag{3-11}
\]

其中，\(S_{global}\) 表示全局匹配分数，\(S_{local}\) 表示局部视角匹配分数，\(\alpha_q\) 表示与查询相关的融合权重。当查询包含较多动作、关系或属性约束时，\(\alpha_q\) 增大；当查询主要描述简单场景或单一对象时，系统更依赖全局匹配分数。该设计避免了固定权重融合对所有查询一视同仁的问题。

### 3.5.4 多视角特征与 Alignment Teacher 的互补关系

Alignment teacher 与 multiview features 之间具有互补关系。Alignment teacher 解决的是“模型应该关注哪些语义对应关系”的问题；multiview features 解决的是“视频侧是否提供足够丰富的局部证据”的问题。如果只有 teacher 而视频侧仍是单一全局向量，局部监督可能缺少足够承载空间；如果只有多视角特征而缺少 teacher 约束，模型又可能无法明确哪些局部证据真正与查询相关。

### 3.5.5 多视角增强的边界

本文后续实验也表明，多视角特征并非越多越好。扩大训练查询数量并筛选高质量样本后，系统在 R@5、R@10 或平均排名上可能出现改善，但 R@1 并未稳定超过 q500 effective222 设置下的最优结果。这说明 Top-1 校准对训练样本分布、监督质量和表示保持约束更敏感。

因此，本文对 multiview features 的理解不是“增加更多特征一定带来更高性能”，而是“在高质量局部监督约束下，为学生模型提供更丰富的视频侧证据”。这一认识对于后续研究同样重要：继续提升系统性能时，应优先关注 near-miss 样本的局部纠错质量，而不是简单扩大训练样本数量或盲目增加视频 token。

## 3.6 联合训练目标与方法消融设计

### 3.6.1 联合训练目标

在完成基础召回和系统型候选优化设计后，本文进一步构建面向细粒度排序校准的联合训练目标。该目标同时考虑基础排序能力、教师软标签、局部对齐、相似负样本区分和表征保持五个方面：

\[
\mathcal{L}=\mathcal{L}_{rank}+\lambda_1\mathcal{L}_{teacher}+\lambda_2\mathcal{L}_{align}+\lambda_3\mathcal{L}_{pair}+\lambda_4\mathcal{L}_{preserve}
\tag{3-12}
\]

其中，\(\mathcal{L}_{rank}\) 用于保持基础检索排序能力，\(\mathcal{L}_{teacher}\) 用于学习 teacher 在候选集合上的软标签分布，\(\mathcal{L}_{align}\) 用于约束查询语义成分与视频局部证据之间的对应关系，\(\mathcal{L}_{pair}\) 用于强化目标视频相对于高相似错误候选的排序优势，\(\mathcal{L}_{preserve}\) 用于防止学生模型在局部样本上过拟合而破坏原有全局表示能力。

该训练目标体现了本文方法的基本取向：基础模型提供稳定的全局召回能力，alignment teacher 和多视角视频特征提供局部对齐监督，pairwise 约束直接面向候选内部排序，表征保持项则用于控制训练过程中的漂移风险。换言之，本文并不是简单叠加多个模块，而是在“稳定召回”和“细粒度排序校准”之间建立受控优化关系。

### 3.6.2 候选范围选择消融

候选范围 Top-K 决定后续模块能够处理的搜索空间。如果 K 过小，目标视频可能无法进入候选集合，后续重排序、teacher 构建和反馈学习均无法发挥作用；如果 K 过大，则会增加索引检索、缓存存储和 teacher 构建成本，并引入更多低质量候选。为确定合适的候选范围，本文统计了 baseline 在不同 K 值下的 candidate recall。

实验结果显示，候选召回率从 Top-1 到 Top-10 提升明显，从 Top-10 到 Top-30 仍有一定增益，但 Top-30 之后边际收益开始变缓。具体而言，Top-30 的候选召回率已经达到 83.78%，而从 Top-30 增加到 Top-40 仅提升 2.58 个百分点，从 Top-40 增加到 Top-50 仅提升 1.94 个百分点。这说明继续扩大候选范围会带来更高计算成本，但收益逐渐降低。

因此，本文后续 teacher 构建和候选分析主要围绕 Top-30 附近的候选集合展开。这样的设置能够较好地平衡候选覆盖率和计算成本，也与本文研究重点一致：在目标视频已经进入候选集合的情况下，进一步提升其在候选内部的排序位置。

### 3.6.3 视频级聚合方式消融

视频级聚合方式直接影响 baseline 表示质量。本文比较了 mean pooling 与 max pooling 两种设置。Mean pooling 将同一视频的多个片段特征进行平均，能够稳定整合视频整体语义；max pooling 更强调局部高响应片段，在某些局部证据明显的场景中可能有优势，但也更容易放大噪声片段对最终排序的影响。

快速验证实验表明，在相同 q200 设置下，mean pooling 的 R@1、R@5 和 R@10 均明显高于 max pooling。其中，mean pooling 的 R@1 为 56.5，而 max pooling 的 R@1 为 40.5。这一结果说明，在本文当前特征与数据设置下，稳定聚合多个片段信息比强调单个最高响应片段更可靠。因此，本文后续 baseline、teacher 构建和细粒度增强实验均采用 mean pooling 作为统一设置。

需要注意的是，该实验使用的是 pooling smoke test 子集，其绝对指标不能与所有正式主实验直接横向比较；但在相同子集、相同模型和相同 Top-K 条件下，mean pooling 明显优于 max pooling，因此足以支撑本文选择 mean pooling 作为基础设置。图3-4(b) 展示了这一对比结果。

### 3.6.4 教师训练规模与监督质量消融

Teacher supervision 的训练规模并非越大越好。本文在实验过程中分别尝试了 q500、q800 以及后续 q1500 高质量样本筛选设置。结果表明，q500 已经能够提供有效监督；继续扩大到 q800 时，R@1 没有继续提升，只在 R@10 和平均排名上出现轻微变化；进一步扩大到 q1500 并进行高质量样本筛选后，R@5、R@10 或 MnR 可能有所改善，但 R@1 并未稳定超过 q500 effective222 设置下的主结果。

这一现象说明，细粒度表征增强的关键不只是训练样本数量，而是样本是否接近模型真实错误边界、teacher 信号是否可靠、以及训练目标是否能够稳定作用于 Top-1 排序。对于自然语言视频检索而言，普通样本数量增加可能改善更宽范围内的召回表现，但 Top-1 校准更依赖 near-miss 样本和局部排序约束。

因此，本文最终选择以 q500 effective222 作为主路线的核心训练设置，并将 q800/q1500 实验作为训练规模敏感性分析。这样的写法能够避免把未稳定提升的扩展实验包装成主结果，同时也能体现本文对实验过程的审慎分析。图3-4(c) 展示了训练规模与监督质量相关实验的趋势。

### 3.6.5 核心表征增强消融

在确定基础候选范围、视频级聚合方式和训练规模后，本文进一步对核心创新模块进行消融分析。消融路线包括：基础召回模型、加入 alignment teacher、加入门控校准、加入教师目标集合、加入 alignment teacher 与 multiview features 的联合增强，以及扩大高质量样本筛选后的进一步检验。该设计能够分别回答三个问题：alignment teacher 是否有效，多视角视频特征是否能够进一步提升性能，以及性能提升是否仅由训练样本数量增加造成。

### 3.6.6 消融结果综合分析

综合上述消融实验，可以得到三点结论。第一，Top-30 附近的候选范围已经能够覆盖较高比例目标视频，后续提升重点应放在候选内部排序校准，而不是盲目扩大候选集合。第二，mean pooling 在当前设置下明显优于 max pooling，说明稳定的视频级全局表示是后续细粒度增强的前提。第三，alignment teacher 与 multiview features 的组合带来了当前最稳定的 Top-1 提升，且 adapter 优于 fused score，说明性能增益主要来自学生模型表示能力的改善，而不是后端分数融合。

这些结果共同支撑了本文的方法主线：先构建稳定高效的全局召回底座，再通过局部对齐监督和多视角视频证据提升候选内部排序能力。本文的创新点并非简单堆叠 rewrite、rerank、teacher 和 memory 等模块，而是通过实验逐步证明：当基础召回已经较为稳定时，真正能够推动 R@1 提升的是面向局部语义证据的表征增强。

## 3.7 错误驱动反馈学习机制

### 3.7.1 失败样本识别

在系统运行过程中，失败样本主要表现为目标视频未排在首位，或目标视频虽然进入候选集合但排名较低。本文将这类样本记录到反馈日志中，并进一步分析其错误类型。错误类型包括 object、relation、person_attribute 和 action 等，这些类型与本文细粒度表征增强关注的语义维度保持一致。

失败样本并不都适合作为训练信号。若目标视频完全没有进入候选集合，说明基础召回存在较大偏差，直接进行局部排序学习可能引入噪声；若目标视频已经接近前列但未排在首位，则更适合作为 near-miss 样本，用于训练模型区分正确目标和相似错误候选。

### 3.7.2 Feedback Teacher 构建

Feedback teacher 的目标是从失败样本中生成高价值监督信号。与平均学习所有样本不同，本文更关注具有纠错价值的失败样本，即模型已经找到相关候选但未能正确排序的样本。此类样本能够直接反映模型当前排序边界的不足。

在构建 feedback teacher 时，系统会记录查询、候选排序、GT rank、错误类型、候选相似度和不确定性等信息。只有当样本满足一定质量条件时，才会被加入 memory 或用于后续训练。这样可以减少低质量反馈对模型的干扰。

### 3.7.3 Memory 质量控制

为了判断持续学习是否有效，本文记录 memory 的数量和质量指标，包括 accepted 样本数、accepted_gt_rank_mean、accepted_top1_is_gt_rate 和 accepted_uncertainty_mean 等。理想情况下，随着学习轮次增加，memory 数量应逐步增加，同时不确定性不应明显变差，GT 平均排名应逐步下降，Top-1 命中率应逐步上升。

当前实验表明，memory 在 safe_dev 上具有一定正向证据，但其收益尚未稳定迁移到 locked 1kA。这说明反馈学习闭环已经具备可运行性，但仍需要更可靠的样本筛选、teacher 构建和协议间泛化控制。

### 3.7.4 Acceptance-Gated Promotion

为了避免持续学习过程中出现性能退化，本文设计 acceptance-gated promotion 机制。每一轮候选模型训练完成后，系统先在验证协议上评估其性能，只有当候选模型超过当前最佳模型时，才允许晋升为新的 best model。若候选模型只改善辅助损失或局部指标，但降低主要检索指标，则不会被接受。

该机制的意义在于将自学习过程从“盲目更新”转变为“受控晋升”。对于实际检索系统而言，持续学习不应只追求模型参数不断变化，而应确保每次模型更新都能带来可验证的性能收益。

### 3.7.5 持续学习机制定位

在本文中，持续学习机制属于扩展探索，而不是最终主结果来源。当前最稳定的 locked 1kA 主结果仍来自 alignment teacher 与 multiview features 的细粒度表征增强。持续学习部分的价值在于建立了从检索失败、反馈记录、样本筛选、候选训练到门控晋升的完整闭环，为后续构建能够持续优化的视频检索 agent 提供基础。

因此，本文不会将持续学习结果过度表述为已经完全实现“越学越强”的系统，而是谨慎地将其定位为初步验证。这样的表述更符合当前实验结果，也更有利于体现论文的严谨性。

### 3.7.6 错误驱动反馈学习消融

为了判断错误驱动反馈学习是否真正带来正向作用，本文进一步对不同 memory 策略进行消融。实验设置包括无反馈学习、当前 memory、严格 memory、放宽 memory、反馈 replay 以及近错 pairwise 学习。其中，无反馈学习用于观察不使用错误反馈时的表现；严格 memory 用于验证过强筛选是否会损失有效样本；放宽 memory 用于验证增加样本数量是否带来收益；反馈 replay 用于检验在当前最佳模型基础上加入错误样本回放是否能够改善更宽范围内的召回；近错 pairwise 学习则用于验证只学习 rank 2-5 near-miss 样本是否能够推动 Top-1。

因此，本文对持续学习机制采取审慎结论：该机制已经具备局部有效性，能够在不降低 R@1 的条件下改善 R@5、R@10 和平均排名；但其 Top-1 稳定增益仍不足，不能替代 alignment teacher 与 multiview features 作为最终主贡献。后续研究若要进一步推进这一方向，应重点提高 feedback teacher 的质量，并避免让少量 near-miss 样本对学生表示造成过强扰动。

## 3.8 本章小结

本章围绕自然语言视频检索中的候选排序问题，提出了基于细粒度对齐增强的方法框架。首先，本文构建了基于预训练视觉语言模型和 FAISS 向量索引的基础召回流程，保证系统具备高效候选检索能力；其次，本文分析了查询改写和候选重排序在系统层面的辅助作用，并指出其收益具有一定局限；最后，本文重点提出 alignment teacher 与 multiview features 相结合的细粒度表征增强方法，通过局部语义监督和多视角视频证据改善学生模型的候选内部排序能力。

本章的核心结论是：本文主增益并非来自简单后处理分数融合，也不是来自训练样本数量的盲目扩大，而是来自学生检索模型表示能力的改善。Alignment teacher 提供局部语义对齐监督，multiview features 提供更丰富的视频侧证据，两者共同提升了模型对相似候选的区分能力。该方法为后续系统实现和实验验证奠定了基础。

# 第4章 自然语言视频检索系统设计与实现

第3章已经从方法角度介绍了本文提出的细粒度对齐增强检索方法。本章进一步说明该方法如何被组织为一个可运行、可测试、可复现实验结果的自然语言视频检索系统。系统实现不仅包括基础的视频特征提取和向量检索，也包括查询改写、候选重排序、alignment teacher、多视角特征、反馈日志和前端可视化等模块。为避免第4章与第3章重复，本章重点关注系统模块划分、数据流组织和工程实现方式。

### 4.1.3 数据流与模块交互关系

系统数据流可以分为离线流和在线流。离线流从原始视频和标注文件开始，依次完成 manifest 构建、视频片段化、视觉语言特征提取和 FAISS 索引构建。该流程只需在数据或模型发生变化时重新执行，能够避免在线阶段重复处理视频内容。

在线流从用户输入查询开始。系统首先对查询进行编码，并在 FAISS 索引中召回候选视频；如果启用选择性改写，则系统会在检索前对含混查询进行语义补充；如果启用 rerank，则系统会对 Top-N 候选进行进一步排序。最终结果被送入前端页面，展示 Top-5 视频、GT rank、检索模式和历史记录。

学习流主要发生在实验阶段。系统根据 teacher supervision、多视角特征和失败样本训练 adapter，并将每次训练的 summary、checkpoint、quick_eval 和 memory 写入输出目录。候选模型只有在通过评估门控后才会被记录为可晋升模型。该设计保证了实验结果可追踪，也降低了错误反馈直接污染模型的风险。

### 4.1.4 系统设计原则

本文系统实现遵循可复现、可扩展和防泄露三个原则。可复现体现在所有实验均通过命令行脚本执行，并将结果写入统一的 JSON summary、日志文件和图表目录；可扩展体现在检索、改写、重排序、表征增强和前端展示模块之间保持相对独立，便于后续替换模型或增加新的学习策略；防泄露体现在训练、验证和 locked 测试协议严格分离，locked 1kA 不参与模型训练和反馈学习。

## 4.3 数据预处理与清单构建实现

### 4.3.1 原始视频与标注解析

系统首先读取 MSR-VTT 视频文件和文本标注，并将视频编号、视频路径、查询文本和数据划分信息统一整理。由于后续检索、评估和反馈学习均依赖视频 ID 与查询标注之间的对应关系，因此清单构建必须保证每条记录具有稳定且可追踪的标识。

预处理后的 manifest 文件为后续模块提供统一入口。视频特征提取模块根据 manifest 找到视频片段路径；检索模块根据 manifest 将片段级结果映射回视频级结果；评估模块根据查询文件中的 GT 信息计算 R@1、R@5、R@10、MedR 和 MnR。

### 4.3.2 查询子集构建

为了兼顾实验效率和评估可信度，本文构建了不同用途的查询子集。训练侧使用 train 9k 安全子集构建 teacher supervision 和 feedback memory；验证侧使用 safe_dev 进行候选模型选择；locked 1kA 作为固定报告协议，仅用于最终检索性能展示。

在开发过程中，本文还使用 q200 子集进行快速消融验证。q200 的作用是降低实验迭代成本，快速比较不同方法设置的相对变化；正式结论仍需结合 locked 1kA full 结果进行说明。这样的设置既保证了实验效率，也避免将快速消融结果误认为最终完整测试结果。

### 4.3.3 数据泄露控制

数据泄露控制是本文实验设计中的重要部分。系统训练、teacher 构建和反馈学习均不得使用 locked 1kA 的 GT 信息作为训练信号。locked 1kA 只用于固定报告和最终结果分析，不能参与样本筛选、模型选择或持续学习晋升。

这一原则在系统实现中通过数据文件和实验命令共同保证。训练命令使用 safe_train 查询文件，候选选择使用 safe_dev，最终报告再使用 locked 1kA。每次实验输出的 summary 中都会记录 train_manifest、train_queries、eval_manifest 和 eval_queries，便于检查实验协议是否正确。

## 4.4 基线检索模块实现

### 4.4.1 视频特征离线存储

基线检索模块首先对视频片段进行离线特征提取，并将特征写入本地文件。在线检索时，系统只需加载特征矩阵和索引文件，不再重复执行视频编码。该设计显著降低了用户查询阶段的计算压力，也使前端交互具备较好的响应速度。

### 4.4.2 FAISS 索引构建

系统使用 FAISS 对视频特征建立向量索引。查询阶段，文本向量被送入索引中进行相似度搜索，得到 Top-K 片段级候选。随后系统根据片段与视频之间的映射关系，将片段级结果聚合为视频级排序结果。

FAISS 的引入使系统能够在本地环境下完成较快的向量检索。由于视频特征已经离线提取，在线阶段主要耗时集中在文本编码和向量搜索上，能够满足原型系统交互展示需求。

### 4.4.3 视频级聚合与评估

片段级检索结果需要进一步转换为视频级结果。系统根据 seg2vid 映射关系，将同一视频的多个片段分数进行聚合，并输出视频级 Top-K 排序。评估模块根据 GT 视频在排序结果中的位置计算各项指标。

本文主要使用 R@1、R@5、R@10、MedR 和 MnR 评估检索性能。R@1 反映目标视频是否排在首位，是衡量首位排序能力的关键指标；R@5 和 R@10 反映候选召回范围内的覆盖能力；MedR 和 MnR 则从排名分布角度反映整体排序质量。

## 4.5 查询改写与重排序模块实现

### 4.5.1 歧义检测与选择性触发

查询改写模块并不对所有输入统一启用，而是先对查询进行歧义检测。系统根据查询长度、语义成分完整性和表达清晰度判断是否需要调用大语言模型。对于主体、动作或对象约束明显不足的查询，系统触发 rewrite；对于语义已经清晰的查询，系统保留原始输入。

该设计能够降低不必要的 API 调用成本，并减少对清晰查询的语义扰动。所有改写结果都会写入缓存，重复查询时可直接读取缓存结果，从而进一步降低成本和响应时间。

### 4.5.2 LLM 查询改写

当查询被判定为需要改写时，系统调用大语言模型生成语义补充结果。改写提示强调保持原始意图，不新增与原查询无关的对象、场景或动作。改写后的文本会重新进入文本编码器，并与视频索引进行匹配。

该模块主要用于处理短查询或语义省略查询。实验结果显示，rewrite 对部分含混查询有效，但对 MSR-VTT 中大量本身清晰的查询提升有限。因此，系统最终将 rewrite 作为可选增强项，而不是默认主路径。

### 4.5.3 候选重排序与缓存

候选重排序模块在基础召回结果的 Top-N 范围内运行。系统将查询和候选视频语义信息组织为提示输入，由大语言模型判断候选与查询的匹配程度，并输出重排序结果。为降低重复计算成本，候选语义和 rerank 结果同样写入缓存。

重排序模块能够在个别案例中修正基础召回排序，但其成本较高，且整体提升不稳定。因此，本文在系统中保留该模块用于对比实验和功能展示，而不将其作为最终主性能来源。

## 4.6 表征增强模块实现

### 4.6.1 Alignment Teacher 接入

Alignment teacher 模块负责读取 teacher supervision 文件，并在 adapter 训练过程中提供局部对齐监督和候选排序软标签。Teacher supervision 文件记录每个训练查询对应的候选集合、GT 信息、teacher 分数和质量控制指标。

训练时，系统根据 reliability gating 筛选高质量 teacher 样本，过滤掉不确定性过高或 GT 排名过差的样本。这样可以减少低质量 teacher 信号对学生模型的干扰，使训练更集中于具有纠错价值的样本。

### 4.6.2 Multiview Features 构建

Multiview features 模块从视频侧构建多视角表示，包括多帧特征、局部片段特征和多时间窗特征。系统将这些特征保存为 `.npz` 文件，并在训练时根据候选视频 ID 对齐读取。

该模块的作用是增强视频侧证据表达。Alignment teacher 负责指出哪些语义成分需要对齐，而 multiview features 提供可供对齐的多视角视频证据。两者结合后，学生模型能够学习更细粒度的文本视频匹配关系。

### 4.6.3 Adapter 训练与模型保存

本文使用轻量 adapter 对学生检索模型进行表征校准。训练完成后，系统会保存模型 checkpoint、实验 summary、quick_eval 结果和 memory 文件。summary 中记录训练参数、样本数量、使用的 teacher 文件、多视角特征文件以及各项检索指标。

这种实现方式使每次实验都具有可追踪性。论文中的主结果、消融结果和失败分析均可回溯到对应 summary 文件，避免只凭终端输出记录实验结果。

## 4.7 前端交互与日志可视化实现

### 4.7.1 首页与检索输入

前端系统提供自然语言查询输入框、随机测试查询按钮和检索参数选择功能。用户可以直接输入自然语言查询，也可以从测试集中随机抽取 query 进行演示。对于测试集 query，系统可以展示 GT rank；对于用户自由输入的自然语言查询，由于不存在 GT 标注，系统只展示检索结果并允许用户提交反馈。

### 4.7.2 结果展示与历史记录

检索完成后，前端页面展示 Top-5 视频结果，并支持视频播放。系统同时记录最近10次搜索历史，用户可以点击历史记录重新打开对应结果页。该功能便于比较不同查询、不同检索模式和不同模型设置下的输出差异。

### 4.7.3 学习日志与消融图展示

前端系统还提供学习日志和消融图展示区域。学习日志记录每次反馈学习的候选模型、是否晋升、主要指标变化和拒绝原因；消融图展示 baseline、rewrite、rerank、alignment teacher 和 multiview features 等实验结果。该设计使系统不只是检索演示页面，也能作为论文实验结果的可视化入口。

## 4.8 本章小结

本章介绍了自然语言视频检索系统的设计与实现。系统采用分层架构，离线构建层负责视频特征和索引，在线检索层负责查询处理和候选召回，表征增强与学习层负责 alignment teacher、多视角特征和 feedback memory，交互展示层负责前端检索、历史记录和日志可视化。

与第3章侧重方法原理不同，本章重点说明各模块如何在工程上组织和运行。通过统一的数据清单、实验 summary、图表目录和前端展示，本文系统能够支撑方法验证、功能测试和论文结果展示。下一章将在此基础上对系统功能、检索效果、响应效率和典型案例进行测试分析。

## 5.1 测试环境与测试协议

### 5.1.1 数据集与协议划分

本文使用 MSR-VTT 数据集进行实验。训练侧使用 train 9k 安全子集构建 teacher supervision、multiview features 和 feedback memory；验证侧使用 safe_dev 进行候选模型选择；locked 1kA 作为固定报告协议，用于最终检索性能展示。为提高实验迭代效率，部分消融实验使用 1kA q200 子集进行快速验证。

需要说明的是，q200 子集用于开发过程中的方法比较，能够快速反映不同模块的相对变化；locked 1kA full 则用于最终结果报告。本文在实验记录中严格区分二者，避免将快速消融结果与完整测试结果混淆。

### 5.1.2 评价指标设置

本文使用 R@1、R@5、R@10、MedR 和 MnR 作为主要评价指标。其中，R@1 表示目标视频是否排在首位，是衡量系统首位排序能力的关键指标；R@5 和 R@10 表示目标视频是否出现在前5或前10个结果中，用于衡量候选召回覆盖能力；MedR 表示目标视频排名中位数；MnR 表示目标视频平均排名。

由于本文的核心目标是改善候选内部排序能力，因此 R@1 是最重要的主指标。R@5 和 R@10 用于辅助判断模型是否改善了更宽范围内的召回表现；MedR 和 MnR 则用于观察整体排名分布是否发生变化。

## 5.2 功能测试

### 5.2.1 查询输入功能测试

系统首页支持两种查询方式：一种是用户手动输入自然语言查询，另一种是从测试查询集中随机抽取 query。随机查询功能主要用于论文演示和系统测试，能够快速查看系统在已有标注样本上的检索表现；手动输入功能则用于模拟真实用户检索场景。

测试结果表明，系统能够正确接收两类输入，并根据用户选择的检索参数执行相应流程。对于测试集 query，系统能够返回 GT rank；对于用户自定义 query，由于不存在 GT 标注，系统不会显示 GT rank，而是提供结果展示和反馈入口。

### 5.2.2 检索结果展示测试

检索完成后，系统会自动跳转至结果页面，并展示查询文本、检索模式、Top-5 视频结果和视频播放区域。对于测试集 query，页面额外显示 GT rank，用于判断目标视频在当前排序中的位置。

测试结果表明，Top-5 视频能够正常加载和播放，检索结果能够按照模型返回的排序显示。该功能保证了系统不仅能够输出离线指标，也能够以用户可理解的方式展示检索结果。

### 5.2.3 历史记录与学习日志测试

系统保留最近10条搜索记录，并提供 Open 按钮用于重新打开对应结果页。历史记录采用滚动区域展示，避免页面内容过长影响整体布局。同时，系统提供学习日志页面，用于展示反馈学习过程中的候选模型、指标变化和晋升结果。

测试结果表明，历史记录能够正确保存最近查询，Open 跳转能够重新进入对应结果页面；学习日志能够展示已执行的自学习实验结果，包括被接受和被拒绝的候选模型记录。这为后续分析系统是否具备持续学习能力提供了可视化基础。

### 5.2.4 消融图与实验结果展示测试

前端系统还支持展示消融实验图和主要结果图。通过该功能，用户可以直接查看 baseline、rewrite、rerank、alignment teacher、multiview features 和 continual learning 等模块的对比结果。

该功能的意义在于把实验结果与系统演示结合起来，使论文中的方法验证不只停留在表格层面，也能够通过页面形式展示系统从查询到结果、从失败样本到学习日志的完整闭环。

## 5.3 检索结果验收

### 5.3.1 测试入口与协议一致性

第3章已经从算法角度给出了候选范围、视频级聚合方式、教师训练规模、核心表征增强和错误反馈学习的消融分析，因此本节不再重复展开方法选择原因，而是从系统测试角度检查最终检索链路是否能够在固定协议下稳定运行。测试时，系统统一读取 MSR-VTT locked 1kA 查询文件和对应 manifest，训练侧样本、teacher supervision 与 feedback memory 均不从 locked 1kA 中构造，避免训练与测试边界混淆。

系统测试包括两类协议：一类是 q200 快速验收，用于验证前端检索、日志记录、视频播放和结果展示是否正常；另一类是 locked 1kA full 验收，用于报告最终系统在完整固定测试集上的检索效果。二者的功能定位不同：q200 更适合快速复核系统状态，full 1kA 更适合作为论文最终报告指标。

### 5.3.2 最终模型检索结果验收

系统最终检索路径采用第3章确定的 alignment teacher 与 multiview features 联合增强模型。表5-2给出了系统验收阶段保留的主要结果。需要说明的是，表中结果用于说明最终系统可达到的检索水平；至于为什么选择 Top-30、为什么采用 mean pooling、为什么 q500 监督优于继续扩大样本，以及 alignment teacher 与 multiview features 如何分别贡献性能，均已在第3章方法消融中展开。

**表5-2 最终系统检索结果验收**

| 测试协议 | 检索路径 | R@1 | R@5 | R@10 | MedR | MnR |
|---|---|---:|---:|---:|---:|---:|
| 1kA q200 | Baseline | 47.5 | 65.0 | 72.0 | 2.0 | 17.32 |
| 1kA q200 | Alignment + Multiview Adapter | 50.5 | 64.5 | 73.5 | 1.0 | 20.42 |
| 1kA full | Baseline | 38.3 | 60.6 | 70.3 | 3.0 | 29.92 |
| 1kA full | Alignment + Multiview Adapter | 38.7 | 61.1 | 70.9 | 3.0 | 29.11 |

从验收结果看，增强模型在 q200 快速验收中将 R@1 从 47.5 提升到 50.5，并将 MedR 从 2.0 降至 1.0，说明系统在首位排序稳定性上获得改善。在 locked 1kA full 验收中，增强模型同样在 R@1、R@5、R@10 和 MnR 上保持正向变化，说明该检索路径并非只在快速子集上有效。由于 full 1kA 查询数量更多、样本覆盖更充分，其绝对指标低于 q200 属于正常现象；本文最终报告时以 locked 1kA full 作为正式协议，以 q200 作为开发过程中的快速复核依据。

### 5.3.3 检索输出完整性测试

除离线指标外，系统还需要保证每次检索能够生成完整、可追踪的输出结果。测试结果表明，系统能够返回查询文本、检索模式、Top-5 候选视频、候选排序分数、GT rank 和视频播放入口。对于随机测试 query，系统能够根据标注文件显示 GT rank；对于用户自行输入的自然语言查询，由于不存在标注答案，系统不显示 GT rank，而是提供反馈入口，用于记录用户对结果的判断。

这一设计使系统同时支持离线实验和在线演示：在论文实验中，GT rank 可用于计算 Recall 和排名指标；在真实交互中，用户反馈可被写入日志，作为后续 feedback teacher 和 memory 构建的候选来源。也就是说，第5章关注的是系统是否能够完整呈现检索结果和反馈链路，而不是再次论证每个算法模块的消融效果。

### 5.3.4 结果文件与日志复核

系统每次评测都会生成 summary 文件，用于记录测试协议、模型路径、检索指标和关键运行参数。该机制可以保证实验结果具备可复查性，避免只依赖终端输出记录结果。对于前端交互检索，系统还会写入历史搜索记录和学习日志，记录查询内容、检索模式、反馈状态和候选模型晋升结果。

日志复核显示，最终主结果来自 alignment + multiview adapter，而不是 rewrite/rerank 后处理路径，也不是尚未稳定晋升的 continual candidate。这一记录与第3章消融结论保持一致：本文的主要有效增益来自学生检索表示的细粒度增强。第5章保留这一复核结论，是为了说明最终系统调用路径与论文主方法一致，而不是将其作为新的方法消融实验重复展开。

## 5.5 响应时间与系统可用性分析

### 5.5.1 Baseline 响应时间

由于视频特征已经离线提取，baseline 在线阶段主要包括文本编码、向量检索和视频级聚合。q200 测试结果显示，baseline 平均检索时间处于几十毫秒量级，能够满足原型系统的在线交互需求。

这一结果说明，本文采用的双塔编码和 FAISS 索引适合作为系统底座。只有当基础检索足够轻量时，后续 rewrite、rerank 和表征增强模块带来的额外成本才可以被清楚观察和比较。

### 5.5.2 Rewrite/Rerank 额外开销

Rewrite 和 rerank 需要调用大语言模型，因此会带来更高响应时间和 token 成本。尤其是 rerank 需要对多个候选进行语义比较，其延迟显著高于 baseline。因此，在实际系统中，这类模块更适合作为按需触发的增强功能，而不是所有查询的默认路径。

从系统设计角度看，rewrite 和 rerank 的价值在于提供可解释的语义增强手段，并帮助分析查询表达和候选排序的边界；但从效率和稳定性角度看，最终主路径仍应依赖轻量、高效且可离线部署的检索模型。

### 5.5.3 前端交互可用性

前端测试表明，系统能够完成自然语言输入、随机 query 抽取、结果播放、历史记录、反馈记录和实验图展示等功能。对于毕业设计系统而言，这些功能能够较完整地展示从模型检索到用户交互的全过程。

同时，前端页面也为后续真实反馈学习提供入口。用户在自然语言查询场景下可以对结果进行反馈，系统可将这些反馈写入日志，为后续构建更稳定的 self-learning retrieval agent 提供数据基础。

### 5.6.4 失败案例原因分析

从 failure diagnosis 结果看，当前系统的主要失败类型集中在 object、relation、person_attribute 和 action 等维度。这说明系统瓶颈并不是单纯候选范围不足，而是局部语义证据仍未被完全建模。许多失败样本并非完全无关视频被排到前列，而是候选视频在整体场景或主体层面与查询相似，但在关键对象、人物属性或动作关系上与目标视频存在差异。

这一现象解释了为什么继续扩大训练样本数量没有稳定带来 R@1 提升。对于首位排序而言，模型需要学习的是正确视频与相似错误候选之间的细微差异，而不是简单学习更多普通样本。后续若要进一步提升 locked 1kA 上的 R@1，应优先针对 object、relation、person_attribute 和 action 等错误类型构建更强的局部监督。

## 5.7 本章小结

本章从系统测试角度对本文自然语言视频检索系统进行了分析。功能测试表明，系统能够完成查询输入、随机 query 抽取、Top-5 视频播放、GT rank 展示、历史记录、反馈日志和消融图展示等主要功能；检索效果测试表明，baseline 已具备较好的候选召回能力，而 alignment teacher 与 multiview features 结合后能够进一步提升首位排序能力；响应时间分析表明，离线特征提取和 FAISS 索引能够保证系统具有较好的在线交互效率。

实验结果进一步说明，本文主增益来自细粒度表征增强，而不是 rewrite/rerank 或简单后处理分数融合。持续学习闭环已经具备基本运行能力，但其 locked 1kA 增益尚不稳定，因此本文将其作为扩展探索而非最终主结果。总体来看，本章实验结果与第3章方法设计、第4章系统实现保持一致，支撑了本文“以细粒度对齐增强提升自然语言视频检索排序能力”的研究主线。
